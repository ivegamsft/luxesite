## Task Summary

Broke the repetitive section-heading pattern across FAQ, Tiers, and ConciergeForm. Each section now has a heading treatment matched to its purpose — eliminating the #1 AI-template tell of uniform eyebrow → h2 → subtitle in every section.

## Implementation

### Section Heading Strategy

Defined a heading treatment matrix ensuring variety while maintaining hierarchy:

| Section Type | Treatment | Components |
|---|---|---|
| **Discovery** | Full eyebrow + heading | Gold uppercase label + fluid-2xl h2 (Destinations, Experiences) |
| **Utility** | Understated label | Left-aligned fluid-xl, medium weight (FAQ) |
| **Pricing** | Inline flex row | Label + tagline, cards lead (Tiers) |
| **Form** | Conversational prose | Mixed-weight sentence, sr-only h2 (ConciergeForm) |

### Component Changes

#### FAQ.tsx
- Removed gold eyebrow (`text-aurora-gold text-xs uppercase`)
- Left-aligned label only (`font-medium text-aurora-white/80`)
- Reduced visual weight from centered + uppercase → quiet, left-aligned utility label

#### Tiers.tsx
- Changed layout from stacked (eyebrow above heading) → **inline flex row**
- Label and tagline sit beside each other, left-aligned
- Tier cards now lead the section (visual priority)
- Removed `text-center` and repositioned to left

#### ConciergeForm.tsx
- Replaced formal eyebrow + heading → **conversational mixed-weight prose**
- Reads like a warm invitation: "Ready to design your next journey? ..."
- Actual `<h2>` preserved for accessibility but marked `sr-only` (screen-reader only)
- No visual heading — prose line leads visually

### Rationale

Human-designed luxury sites never repeat the same heading pattern across sections — that uniform structure is the tell-tale signature of AI-generated content. By varying treatment per section type (discovery vs. utility vs. pricing vs. form), we restore editorial intentionality and break the template feel.

**Rules established:**
- Max 2–3 sections per page may use the full eyebrow+heading pattern
- Screen reader hierarchy always preserved (`sr-only` headings where needed)
- New sections should consult this matrix before defaulting
